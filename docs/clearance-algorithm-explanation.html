Door Reduction Clearance Algorithm

Explanation of the original VB implementation in legacy-access-vba/ClearanceCheck.bas and the converted Node implementation in src/clearanceCheck.js.

Main idea: the clearance algorithm checks whether the new storm/security door hardware can physically clear the customer's existing lock hardware and glass clearance. If the default configuration does not work, it tries a fixed sequence of accepted modifications and returns the first one that passes.

Where The Algorithm Lives

The original Access/VB code is in legacy-access-vba/ClearanceCheck.bas. The converted JavaScript version is in src/clearanceCheck.js. In the Node flow, the clearance input is assembled in src/calcDoorOutput.js by buildClearanceInput(), then passed into chkClearance(input).

chkClearance()
  -> chkDBKLoc()
    -> chkClear()
      -> chkLoc()

Each function has a specific responsibility. chkClearance() validates and prepares the input. chkDBKLoc() chooses the correct lock measurements. chkClear() tries possible solutions in priority order. chkLoc() performs the actual interference test.

What Clearance Means Here

The word "clearance" has two meanings in this project:

  1. Glass/build-out clearance: the door needs enough spacing for normal glass. If the existing clearance is too small, the algorithm tries lath or tube frame build-outs.
  2. Hardware interference clearance: the new door's deadbolt, knob, or lever must not collide with the customer's existing deadbolt or knob.

Step 1: Door Height Adjustment

The original clearance constants are based on a standard 79" door height:

const DOOR_HEIGHT = 79;

The algorithm calculates:

iLocAdjust = actualDoorHeight - 79

Then every lock location range is shifted by that amount. For example, a 4-Way Mortise deadbolt normally occupies 36.875" to 38.875". If the actual door height is 80", the adjusted range becomes 37.875" to 39.875".

Step 2: Glass Clearance

The glass clearance rule starts with this constant:

const NORMAL_GLASS = 0.25;

The algorithm takes the smaller of the deadbolt and knob clearance values:

lowestClearance = Math.min(DBProj, KProj)
iGlassAdj = 0.25 - lowestClearance
Condition Meaning
iGlassAdj <= 0Normal glass clearance is already acceptable.
iGlassAdj <= 0.25A 1/4" lath may solve the glass clearance issue.
iGlassAdj <= 0.375A 3/8" lath may solve the issue.
iGlassAdj <= 1A 1" tube frame may solve the issue.
iGlassAdj > 1The check fails because even a tube frame cannot create enough glass clearance.

Step 3: Lock-Specific Ranges And Projections

Every lock family has hard-coded ranges for where its deadbolt, knob, reverse deadbolt, reverse knob, lever, and reverse lever will land. It also has projection values for how far the new hardware sticks out.

Example for 4-Way Mortise:

MDL = 36.875  // deadbolt lower bound
MDU = 38.875  // deadbolt upper bound
MKL = 40.375  // knob lower bound
MKU = 42.75   // knob upper bound

MDP = 0.625   // deadbolt projection
MKP = 2.5     // knob projection
MLP = 2       // lever projection

After applying the height adjustment, these ranges become the vertical zones where the new door hardware may interfere with existing hardware.

Step 4: The Collision Test

The real pass/fail logic is in chkLoc(). It checks four possible collisions:

  1. Existing deadbolt against new deadbolt.
  2. Existing deadbolt against new knob or lever.
  3. Existing knob against new knob or lever.
  4. Existing knob against new deadbolt.

A configuration fails when both of these are true:

existing hardware location overlaps the new hardware vertical range
AND
new hardware projection > existing clearance + build-out adjustment

So the algorithm is asking: "Does the new hardware land at the same height as the existing hardware, and if so, does it stick out too far for the available clearance?"

Example

If the existing knob has 1.5" clearance and the new lever projects 2":

Configuration Comparison Result
No build-out2 > 1.5 + 0Fail
1/4" lath2 > 1.5 + 0.25Fail
3/8" lath2 > 1.5 + 0.375Fail
1" tube2 > 1.5 + 1Pass

Step 5: Recommendation Order

The algorithm does not search every possible solution and rank them mathematically. It tries a fixed business-priority sequence and returns the first option that passes.

4-Way Mortise And Yale

  1. No adjustment
  2. Reverse lock
  3. Lever
  4. Reverse lever
  5. 1/4" lath
  6. 3/8" lath
  7. 1/4" lath and lever
  8. 3/8" lath and lever
  9. Reverse and 1/4" lath
  10. Reverse and 3/8" lath
  11. Reverse lever and 1/4" lath
  12. Reverse lever and 3/8" lath
  13. Tube frame
  14. Tube frame and lever
  15. Reverse tube frame
  16. Reverse lever and tube frame
  17. Fail

Slim Line, Bee Line, And Deluxe

  1. No adjustment
  2. 1/4" lath
  3. 3/8" lath
  4. Tube frame
  5. Fail

Special Yale Upgrade Rule

There is one special fallback. If lock type 61 Yale/Kwikset fails completely, the algorithm tries the same measurements again as lock type 60, which is 4-Way Mortise.

if Yale fails:
  try 4-Way Mortise
  if 4-Way passes:
    return the passing recommendation
    append "Upgrade to 4-Way Mortise Lock is required"

This means a Yale failure can still produce a valid recommendation if upgrading to 4-Way Mortise changes the hardware ranges/projections enough to clear.

Important Implementation Note

The original VB has an explicit BAD_LOCK result for unknown lock types. The current JavaScript mapping converts unknown lock names to 0, but chkClear() does not currently return BAD_LOCK for that value. In practice, an unknown lock usually falls through and returns a general clearance failure instead of "Lock Type not recognized".

Short Summary

The clearance algorithm is a deterministic recommendation engine. It shifts lock ranges based on door height, calculates whether glass needs a build-out, tests whether new lock hardware overlaps existing hardware, and returns the first passing adjustment from a fixed sequence. The most important function is chkLoc(), because that is where physical interference is actually detected.
